# Phantom Relay 今日 24 小时压缩回归计划（3 倍工作量版）

- 制定时间：2026-07-22T09:42:48+0800
- 执行窗口：2026-07-22 09:45 → 2026-07-23 09:45（Asia/Shanghai）
- 压缩规则：原 3 分钟的准备/检查/归档任务压缩为 1 分钟执行单元；每个单元同时推进 3 条工作线。
- 真实等待例外：网页生成、API响应、页面刷新、扩展重载不能人为压缩；必须等真实结果。
- 最终证据：真实 GUI + 真实扩展 + 录制 input/send/response + 调用方 HTTP 非空回复。

## 一、三条工作线

### A线：真实用户 E2E

唯一负责真实调用：

```text
读取录制规范
→ 真实 API/Cherry Studio 请求
→ 真实页面执行
→ 真实录制 response 捕获
→ 调用方收到非空内容
```

### B线：证据与故障定位

只观察、不执行聊天动作：

```text
HTTP body
→ job id
→ claim
→ page event
→ response candidate
→ delta/result
→ 最终 HTTP body
```

CDP只能读状态/日志，禁止输入、点击、Enter、手工 result。

### C线：回归档案与普适特征

每 1 分钟同步记录：

```text
时间戳
场景
录制三要素
结果
失败边界
代码改动
站点特征
下一动作
```

代码写入必须串行；A/B/C可以并行读和记录，但不得三个工作线同时修改同一文件。

## 二、硬门槛

1. 豆包/DLM 非流式先恢复；流式不得继续破坏它们。
2. 第一条真实非流式没通过前，冻结 SSE、并发、tool calling、压力测试。
3. 每轮只允许一个主假设、一个代码边界。
4. 每次真实调用前读取 `docs/RECORDED_STANDARD.md`。
5. 不自动发现 selector，不扫描按钮，不猜 response 区域。
6. Enter 永远先尝试；Enter 多次失败后才允许使用录制 button。
7. 页面有回答但调用方没收到，判失败。
8. 静态测试、queue=0、claim、trace、手工 result 都不算最终成功。
9. 同一假设两轮失败，重新调查；同一边界三轮失败，回滚到最近基线重新设计。
10. 每个轮次都必须写入 `docs/regression/rounds/`。

## 三、1 分钟单元模板

每个 1 分钟单元都执行三件事：

```text
第 1 分钟动作：A线推进一个用户路径动作
第 1 分钟动作：B线确认一个证据边界
第 1 分钟动作：C线写入一条时间戳记录
```

若 A线正在等待真实网页响应：

```text
A线等待真实结果
B线关联同一 job 的证据
C线写入等待状态和当前假设
```

禁止为了“完成一分钟任务”制造假结果。

## 四、24 小时分段计划

### 09:45–10:00｜15 个一分钟单元：基线锁定

每分钟循环：

- A：确认不发送请求，只确认真实 GUI 宿主是否存在。
- B：记录 API、客户端、tab、扩展 marker、Git 状态。
- C：写 `R000-baseline-lock` 的一条记录。

15 分钟产出：

- GitHub `origin/main` 与当前 HEAD；
- 工作树改动文件；
- 当前 API/浏览器状态；
- 豆包/DLM/千问/文心录制三要素；
- `20260722-0945-stage0-baseline.md`。

### 10:00–10:30｜30 个一分钟单元：GitHub基线差异三倍扫描

每 1 分钟并行：

- A：标记豆包/DLM 非流式调用链入口。
- B：对比当前与 origin/main 的发送、response、SSE路径。
- C：把差异写入风险表。

每 5 分钟一个小结：

1. 非流式入口差异；
2. 发送状态机差异；
3. 回复提取/回传差异；
4. SSE相关差异；
5. 高风险文件排序；
6. 选出第一条唯一调查假设。

禁止改代码。

### 10:30–10:45｜15 个一分钟单元：真实宿主与录制核对

- A：确认真实GUI Canary和扩展是否可用。
- B：确认 `/browser/clients`、ready、capabilities、tab域名。
- C：逐项归档 input/send/response原文。

宿主不可用时：立即记 `unverified-host`，停止E2E，不启动临时profile冒充真实环境。

### 10:45–11:15｜30 个一分钟单元：豆包基线短非流式

第一条真实请求前：读取 `RECORDED_STANDARD.md`。

- A：发送一条固定短请求。
- B：按同一 job 追踪 request→claim→send→response→result→HTTP。
- C：每分钟写状态。

真实网页等待期间不制造额外请求。

通过门槛：

```text
HTTP 200
choices[0].message.content 非空
```

失败时不立即改代码，先用剩余分钟分类：发送、录制response、回传、API等待。

### 11:15–11:45｜30 个一分钟单元：豆包三次复验或单边界定位

若第一次成功：

- A：用三个不同短语连续真实调用。
- B：逐次确认调用方body，不用历史trace。
- C：记录成功文本长度、耗时、录制区域和页面状态。

若第一次失败：

- A：不重复发送；保留失败job。
- B：只定位一个失败边界。
- C：写失败轮次，不改代码。

### 11:45–12:15｜30 个一分钟单元：豆包最小修复/回滚

仅当根因已明确：

- 10 分钟：写修复前归档和单一假设；
- 10 分钟：只修改一个边界；
- 5 分钟：重新加载真实扩展/确认新marker；
- 5 分钟：准备同一真实请求。

禁止同时修改发送、response和SSE。

### 12:15–12:45｜30 个一分钟单元：豆包保护性复验

- A：连续三次真实短非流式；
- B：记录每一次调用方body；
- C：生成豆包站点特征档案。

通过后才允许进入DLM；失败则回到豆包，不扩展范围。

### 12:45–13:15｜30 个一分钟单元：DLM/DeepSeek第一次真实非流式

- A：使用DLM自己的录制三要素执行；
- B：记录发送事件和录制response区域证据；
- C：写 `e2e-dlm-short-r1`。

不复用豆包selector、不加域名全局分支。

### 13:15–13:45｜30 个一分钟单元：DLM三次复验或单边界定位

成功：三个不同短语真实调用。
失败：只调查发送/捕获/回传中的一个边界。

每 5 分钟写一次小结，避免再次堆叠猜测补丁。

### 13:45–14:15｜30 个一分钟单元：DLM最小修复/回滚

- 修复前记录；
- 单一假设；
- 单文件或单函数改动；
- 真实扩展重载；
- 同请求复测准备。

如果三轮仍失败，回滚到最近确认可用版本，停止继续加逻辑。

### 14:15–14:45｜30 个一分钟单元：DLM保护性复验

- A：三次真实短非流式；
- B：页面刷新后一次真实请求；
- C：写DLM特征档案和证据表。

必须全部通过，才算两个基础站点恢复。

### 14:45–15:15｜30 个一分钟单元：两站普适边界归纳

将事实分为三栏：

```text
通用执行器能力
站点适配器声明
尚未验证假设
```

检查并记录：

- 是否存在域名硬编码；
- 是否存在自动selector发现；
- 是否存在通用response扫描；
- 是否存在CDP执行入口；
- 是否可能因SSE破坏非流式。

只写整改清单，不做大重构。

### 15:15–16:00｜45 个一分钟单元：非流式保护回归

每 15 分钟一个循环：

```text
豆包真实短非流式
DLM真实短非流式
两次调用方body核对
轮次归档
```

共执行三轮。任何一轮失败，立即锁定失败站点。

### 16:00–16:30｜30 个一分钟单元：千问/文心录制特征

- A：只检查录制三要素。
- B：只确认真实宿主状态。
- C：建立站点特征档案。

没有录制response或button时，只记配置缺口，不猜、不补、不发送。

### 16:30–17:00｜30 个一分钟单元：通用执行器最小整改

仅当15:15–16:00发现明确违规：

- 每 10 分钟只处理一个具体违规；
- 修改前后都归档；
- 不触碰SSE；
- 立即回跑豆包/DLM各一条非流式。

### 17:00–17:30｜30 个一分钟单元：基线再保护

- 豆包一次真实非流式；
- DLM一次真实非流式；
- B线核对实际HTTP body；
- C线写保护结果。

### 17:30–18:00｜30 个一分钟单元：阶段收口

产出：

- 两站非流式通过/失败矩阵；
- 每站特征档案；
- 通用/特例边界；
- 当前唯一阻塞点；
- 下一阶段是否批准SSE。

若非流式任一站未通过：18:00后不进入SSE。

### 18:00–19:00｜60 个一分钟单元：归档与低强度复盘

- 每 5 分钟检查一次档案完整性；
- 清除“页面有字=成功”的错误结论；
- 标记所有 `static`、`bridge`、`e2e`证据等级；
- 不改业务代码；
- 不启动临时浏览器。

### 19:00–19:30｜30 个一分钟单元：SSE批准检查

只有以下全部满足才批准SSE：

- 豆包非流式连续3次通过；
- DLM非流式连续3次通过；
- 刷新后至少一次通过；
- 真实录制response存在；
- 当前扩展marker已确认。

否则重复非流式保护，不做SSE。

### 19:30–20:00｜30 个一分钟单元：第一条真实SSE

- A：发送一条短SSE请求；
- B：记录调用方原始SSE片段；
- C：每分钟归档事件。

通过门槛：

```text
至少一个非空 delta.content
finish_reason
[DONE]
```

### 20:00–20:30｜30 个一分钟单元：SSE单边界定位

若失败，只在以下四类中选一个：

```text
response区域
capture_delta
result回传
SSE渲染/终止
```

不修改发送链，不修改非流式路径。

### 20:30–21:00｜30 个一分钟单元：SSE最小修复与重测准备

- 单一假设；
- 单一边界；
- 单一改动；
- 真实扩展marker；
- 准备同请求重测。

### 21:00–21:30｜30 个一分钟单元：SSE真实复验

同请求两次，不同短语一次。

若失败：SSE标记未通过，回到非流式保护。

### 21:30–22:00｜30 个一分钟单元：第二站点SSE（有条件）

只有第一站SSE真实通过才执行。

第二站点若失败，不回头修改第一站已通过的通用链，先记录站点特征。

### 22:00–22:30｜30 个一分钟单元：同站点多轮

- 第一轮真实请求；
- 第二轮引用第一轮；
- 调用方确认第二轮真实内容；
- 记录conversation/tab复用是否正确。

### 22:30–23:00｜30 个一分钟单元：页面刷新恢复

- 真实GUI刷新；
- 等待录制input/ready；
- 一次真实非流式；
- 失败就停在刷新恢复，不改多轮逻辑。

### 23:00–23:30｜30 个一分钟单元：模型切换

仅当两个站点非流式均通过：

```text
豆包 → DLM → 豆包
```

每次只看调用方body，防止站点回答串线。

### 23:30–00:00｜30 个一分钟单元：双conversation最小并发

最多两个请求，不做高压。

每个调用方必须收到自己的非空回复；否则并发未通过。

### 00:00–00:30｜30 个一分钟单元：错误恢复

只测试一个可控失败：

```text
录制response暂时不可用 / 页面未ready
```

要求：有界失败、job释放、下一次正常请求不被阻塞。

### 00:30–01:00｜30 个一分钟单元：中期总结

- 通过数；
- 失败数；
- 未验证数；
- 每站真实证据；
- 当前唯一阻塞点；
- 下一周期唯一动作。

### 01:00–07:00｜6个一小时稳定窗口，每小时60个一分钟单元

每小时执行三组：

1. 1次豆包短非流式；
2. 1次DLM短非流式；
3. 已通过SSE站点1次SSE复验（若SSE尚未通过则不做）。

其余分钟用于：

- B线归档HTTP结果；
- C线更新特征档案；
- 检查是否出现job残留；
- 若没有 fresh ready 客户端，由后端按请求立即唤醒用户浏览器；不在回归循环中额外启动第二个宿主；
- 不制造临时profile；
- 允许休息，不用空转请求刷数量。

### 07:00–07:30｜30 个一分钟单元：早间非流式复验

豆包、DLM各两次真实请求；调用方body必须非空。

### 07:30–08:00｜30 个一分钟单元：早间SSE复验

仅复验已通过SSE的站点；记录原始SSE和最终拼接文本。

### 08:00–08:30｜30 个一分钟单元：普适特征归纳

将四站档案整理成：

```text
通用协议
通用生命周期
站点适配器能力
站点限制
未验证假设
```

禁止把一次站点现象升级为全局规则。

### 08:30–09:00｜30 个一分钟单元：代码/文档一致性

- README不宣称未验证能力；
- 录制规范和代码一致；
- 主线和轮次记录一致；
- 成功措辞全部有调用方证据；

### 09:00–09:30｜30 个一分钟单元：24小时结果收口

输出：

- 豆包非流式结果；

### 09:30–09:45｜15 个一分钟单元：下一周期决策
