# Phantom Relay 回归主线

> **SUPERSEDED（2026-08-11）**
>
> 本文保留为历史回归记录，不再是实现或验收依据。下文关于 background
> 自动建页、默认 Enter 重试和发送方式降级的内容均已废弃。
>
> 当前权威契约：API 是自动浏览器激活的唯一所有者；background 不创建、
> 不导航、不置顶 provider tab；popup 只能在用户明确操作时打开录制页；
> 完整录制 profile 是执行和回复捕获的唯一边界；每个请求只执行一次录制的
> 发送方式；回复流与完成判定只接受录制 response selector 和 identity；
> 未录制的页面控件无权影响回复完成；network capture 在产品运行时禁用。
> 只有真实 API、真实扩展、真实浏览器和真实网页模型闭环才算通过。

## 唯一目标

从普通使用者角度证明：

```text
真实 GUI 浏览器 + 真实扩展
→ 后端收到请求后立即唤醒浏览器（无 fresh ready 客户端时）
→ 扩展在无目标页时创建已录制 target_url
→ 用户录制 input
→ 默认 Enter 尝试
→ Enter 多次失败后使用用户录制 button（若存在）
→ 只从用户录制 response 区域捕获
→ OpenAI-compatible API / Cherry Studio 收到真实非空回复
```

只有调用方实际收到非空 assistant 内容，才算成功。页面文字、trace、job claim、queue=0、静态测试、手工 result 回传都不算最终成功。

## 阶段顺序

### Stage 0：基线保护

- 记录 GitHub `origin/main` 可用基线。
- 记录当前工作树改动，不把当前改动直接当作可用版本。
- 优先保护已知可用的豆包/DLM 非流式路径。
- 流式改动不得破坏非流式；每轮只改一个边界。

### Stage 1：一个站点、一个短非流式请求

- 使用真实 GUI 浏览器和真实扩展宿主。
- 覆盖浏览器冷启动：浏览器关闭或没有目标页时，先发真实 API 请求，确认后端 wake 与扩展建页发生，再进入录制执行。
- 使用现有用户录制数据，不猜 selector、不自动发现。
- 发送最短固定回复请求。
- 验收只看调用方 HTTP body：HTTP 200 + 非空 `choices[0].message.content`。

### Stage 2：同站点回归

按顺序：短非流式重复 3 次 → 页面刷新后短非流式 → 短 SSE → 第二轮多轮。
任一步失败，停在该站点修复，不进入下一个站点。

### Stage 3：逐站点建立普适特征档案

每个网站只记录站点特征，不把特征硬编码成全局规则：

- 录制 input 的元素类型和受控输入模型；
- Enter 是否有效、失败表现和重试边界；
- 录制 button 的元素类型、点击事件模型和可用状态；
- 录制 response 区域的稳定边界、流式表现和完成信号；
- 页面刷新/复用/多轮行为；
- 已知限制和真实证据。

站点适配器只能声明能力和特征；通用执行器负责统一生命周期、一次发送、回传、超时和恢复。

### Stage 4：最后才扩展

只有所有目标站点的单请求真实闭环通过后，才做：

- SSE；
- 长消息；
- 多轮；
- 模型切换；
- 并发独立 conversation；
- 错误恢复。

## 硬禁止

- CDP 直接输入、点击、Enter 或手工 POST `/browser/result` 作为产品执行。
- 自动发现/猜测 selector。
- 用通用 DOM 扫描替代录制 response。
- 用静态审计结果宣布真实可用。
- 在首条真实非流式未通过前继续扩大功能范围。
- 同一轮同时修改发送、回复捕获、SSE、队列多个边界。

## 每轮必须归档

每一轮在修改前建立时间戳记录，修改后补齐：

- 时间戳；
- 基线/工作树状态；
- 真实用户场景；
- 请求参数和模型；
- 录制三要素；
- 实际 HTTP 状态和响应内容摘要；
- 页面侧证据；
- 改了哪些文件、为什么改；
- 失败边界或成功证据；
- 下一轮唯一动作。

归档目录：`docs/regression/rounds/`。
