# Phantom Relay 录制标准（唯一执行规范）

> **SUPERSEDED（2026-08-11）**
>
> 本文保留为历史设计记录，不再是“唯一执行规范”。下文的 CDP Enter、
> 合成 Enter、自动发现按钮和多阶段 fallback 级联已经废弃，禁止据此恢复。
>
> 当前权威契约：用户必须录制 input、send strategy 和带稳定 identity 的
> response profile；执行器每个请求只回放一次录制的发送动作，不猜 selector、
> 不扫描按钮、不尝试替代发送方式；回复增量和最终结果只能来自录制 response
> 边界；未录制的 stop/cancel 等页面控件不能拥有 completion 判定权；产品运行
> 时禁止 network capture。最终验收必须由真实 API 请求触发真实浏览器和真实
> 网页模型，并由调用方收到完整 OpenAI-compatible JSON 或 SSE。

## 录制的三个阶段

1. **输入框阶段**：录制用户输入框。
2. **发送阶段**：录制发送方式。
   - 默认发送方式永远是回车键（Enter）。
   - 执行时按 4 阶段普适策略迭代，不依赖单一模型配置。
3. **回复区域阶段**：录制回复区域，输出捕获只能使用录制的回复区域。

## 4 阶段普适发送策略（Universal Send Cascade）

每个请求按以下优先级迭代，前一个失败自动降级：

| 阶段 | 方法 | 说明 | 普适性 |
|------|------|------|--------|
| 1 | CDP `Input.dispatchKeyEvent` Enter | Chrome DevTools Protocol 原生按键，`isTrusted:true`，React 可靠检测 | ✅ 所有站点 |
| 2 | 合成 `KeyboardEvent` Enter | Fallback：CDP 不可用时的降级路径 | ⚠️ React 可能忽略 |
| 3 | `findUniversalSendButton()` 自动发现 | 扫描输入框附近所有按钮，关键词匹配（send/发送/arrow…）+ 空间距离评分 | ✅ 跨模型普适 |
| 4 | 录制按钮精确回退 | 用户录制的具体按钮 selector，精确但需要每站点录制 | ⚠️ 站点特定 |

- ✅ 阶段 1（CDP Enter）是普适方案，对所有 React/Vue/Svelte 站点有效。
- ✅ 阶段 3（自动发现）无需任何录制，纯启发式扫描。
- ✅ 阶段 4 是最精确的兜底，只有用户录制的按钮才使用。
- ❌ 禁止跳过阶段 1/3 直接执行阶段 4。
- ❌ 禁止猜测、扫描、自动发现代替阶段 1。

## 三种发送方式优先级

1. **Enter（默认）** → CDP 原生按键（最快，普适）
2. **快捷键** → CDP 组合键（需要录制按键组合）
3. **发送按钮** → `findUniversalSendButton()` 自动发现 → 录制按钮精确回退

## 最小可用标准

- 最少必须有：录制输入框。
- Enter 永远可用（CDP 原生按键，不需要录制）。
- 发送按钮可选录制（用于阶段 4 精确回退）。

## 唯一性与禁止事项

- ✅ 录制数据是参考，非唯一执行路径。
- ✅ 执行链：CDP Enter → 合成 Enter → 自动发现按钮 → 录制按钮。
- ✅ 每个请求最多产生一次逻辑发送。
- ❌ 禁止跳过 CDP 直接使用合成事件。
- ❌ 禁止把 Enter 失败当成不可恢复错误。
- ❌ 禁止把页面上任意变化的文本当成回复；必须匹配录制回复区域。

## 最终验收标准

只有真实使用者视角的闭环才算成功：

真实 GUI 浏览器扩展宿主 → CDP Enter 尝试 → 自动发现按钮 fallback（必要时） → 录制回复区域捕获 → API/Cherry Studio 收到真实非空回复。

静态检查、后端模拟、队列 claim、DOM 探针和历史 trace 只能作为中间诊断证据，不能作为最终成功结果。
